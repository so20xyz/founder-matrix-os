# /fm:help — гишүүний тусламжийн суваг

Гишүүн (Student гэх мэт) дараагийн уулзалт хүртэл ганцаараа үлддэг. Энэ skill тэр зайг нөхнө: **эхлээд өөрөө хариулна, чадахгүй бол л maintainer руу зөв бичсэн issue болгож явуулна.**

- Vault: `${user_config.vault_path}` (доор `<V>`). Repo: `Atlas322/founder-matrix-os`.
- Скрипт: `python3 "${CLAUDE_PLUGIN_ROOT}/skills/help/scripts/fm_help.py"` (доор `fm_help`).
- Дүрэм: `<V>/_system/BOOT.md`. Энэ skill-тэй зөрвөл BOOT ялна.

`/fm:help status` → зөвхөн 6-р алхам (өөрийн issue, ирсэн хариу).

## 0. Эхлээд: энэ асуулт уу, алдаа уу, санаа уу

| Төрөл | Дохио | `--kind` |
|---|---|---|
| **Асуулт** | «яагаад ингэдэг юм», «яаж хийх вэ», «энэ юу гэсэн үг вэ» | `question` |
| **Алдаа** | команд унасан, буруу үр дүн, Traceback | `bug` |
| **Санаа** | «ийм байсан бол», шинэ skill/дүрийн санал | `idea` |

Ангиллыг дотроо тогтоо; гишүүнээс «энэ аль нь вэ» гэж битгий асуу.

## 1. Vault-аас хариул (үргэлж эхэнд)

**Хамгийн түгээмэл тохиолдол: хариу аль хэдийн vault-д байгаа.** Issue үүсгэхээсээ өмнө эдгээрийг энэ дарааллаар хай:

1. `<V>/_system/BOOT.md` — Matrix-ийн дүрэм, дүрүүд, хавтасны утга.
2. Холбогдох skill-ийн `SKILL.md` (`/fm:task`, `/fm:project`, …) — алхам, хориг.
3. `${CLAUDE_PLUGIN_ROOT}/../../CHANGELOG.md` (эсвэл repo clone-ийн `CHANGELOG.md`) — мөр бүр `Яагаад: … · Дүрэм: … · Ном: …` гэж **шалтгаанаа хэлдэг**. Гишүүний асуусан зан байдал хэзээ, яагаад орсныг эндээс ол.
4. `<V>/04-Resources/library/Ном ↔ зарчим ↔ дүрэм.md` — дүрэм бүр аль номын зарчмаас гаралтайг харуулсан зураглал (`basb · para · gtd · atomic-habits · zettelkasten · bmg`).
5. `<V>/04-Resources/library/<ном>.md` — тэр номын «Номын арга» хэсэг.

**Хариултын хэлбэр (гурван мөр, энэ дарааллаар):**

```
<Юу хийх вэ — бодит алхам, команд>
Яагаад: <fm яагаад ингэж ажилладаг — дүрэм эсвэл шийдвэр>
Ном: <BASB | PARA | GTD | Atomic Habits | Zettelkasten | BMG> — <тэр номын зарчим нэг өгүүлбэрээр>
```

Ном тодорхойгүй бол `Ном:` мөрийг **бүү зохио** — орхи. Таамгаар ном холбох нь буруу заавар өгөхөөс дор.

Хариулсан бол **энд зогс.** Issue үүсгэхгүй. Гишүүнээс «ойлгомжтой болов уу?» гэж нэг асуу.

## 2. Шалтгааныг тодруул (нэг удаад нэг асуулт)

1-р алхам хариулж чадаагүй бол **шууд issue бүү бич** — эхлээд асуудлыг хурцал. `superpowers:brainstorming` skill байвал түүнийг ачаал; байхгүй бол энэ дарааллаар, **нэг мессежид нэг асуулт**:

1. Юу хийх гэж байсан бэ? (зорилго, үр дүн — команд биш)
2. Яг юу хийсэн бэ? (команд, товчилсонгүй)
3. Юу болсон бэ? (гарсан үр дүн, алдааны текст)
4. Юу болно гэж бодсон бэ?
5. Өмнө нь юу оролдсон бэ?

Гишүүний хариултыг **эх үгээр нь** хадгал — товчлох нь maintainer-ийн оношийг алдагдуулдаг. Хоёр асуулт нэг мессежид багтаахгүй.

## 3. Нотолгоо цуглуул

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/skills/help/scripts/fm_help.py" env
```

OS, Python, Claude Code, fm plugin хувилбар, `gh` нэвтрэлт. Нэмж: ажилласан команд, алдааны бүтэн текст (бүтэн замыг скрипт өөрөө `<vault>`, `<home>` болгож нууна).

## 4. Ноорог бич (vault-д, GitHub-д биш)

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/skills/help/scripts/fm_help.py" draft "<V>" \
  --kind bug \
  --title "Цаглабар хоосон харагдана" \
  --what "..." --steps "1. ...\n2. ..." --expected "..." --error "..." --tried "..." \
  --command "/fm:update daily"
```

→ `01-GTD/Inbox/<огноо> - Тусламж - <гарчиг>.md`. Note-ийн «## Issue-ийн бие» хэсэг нь GitHub руу явах яг тэр бичвэр.

**Нооргийг гишүүнд бүтнээр нь уншуул** (чухал: энэ нь түүний нэрээр нийтэд гарна). Засах зүйл байвал note-ийг Edit-ээр зас — дахин `draft` хийхгүй.

## 5. Илгээх (зөвхөн гишүүн зөвшөөрвөл)

```bash
python3 ".../fm_help.py" send "<V>/01-GTD/Inbox/<note>.md"            # зөвхөн харуулна, илгээхгүй
python3 ".../fm_help.py" send "<V>/01-GTD/Inbox/<note>.md" --yes      # GitHub-д үүсгэнэ
```

- `--yes`-гүй бол **юу ч илгээгдэхгүй** — эхлээд ингэж ажиллуулж гишүүнд үзүүл.
- Гишүүн «тийм» гэж тодорхой хэлсний дараа л `--yes`. «за», «ойлголоо» гэдэг зөвшөөрөл биш.
- Амжилттай бол note-ийн `issue:` талбарт холбоос, `status: waiting` бичигдэнэ.
- `gh` нэвтрээгүй бол: `gh auth login` хийхийг хэл — token-ийг **хэзээ ч** чи асуухгүй, оруулахгүй.

## 6. Хариу авах (`/fm:help status`)

```bash
python3 ".../fm_help.py" status "<V>"
```

Гишүүний өөрийн issue-ууд, тус бүрийн төлөв, ирсэн хариу, сүүлийн сэтгэгдэл.

Шинэ хариу ирсэн бол:
1. Тэр issue-гийн тусламжийн note-ийг ол (`source: fm-help`, `issue:` таарна), «## Хариу» хэсэгт огноо + хариуг нэм (Read → Edit, байгааг бүү дар).
2. Хариу нь **дүрэм эсвэл ойлголт** бол `/fm:save`-аар атом болго (`04-Resources/Atomic/knowledge/`) — дараагийн удаа 1-р алхамд өөрөө олдоно.
3. Issue хаагдсан бол note-ийн `status: completed`.

## Хориг

- **Гишүүний зөвшөөрөлгүй GitHub-д юу ч илгээхгүй** (`--yes` зөвхөн тодорхой зөвшөөрлийн дараа).
- Vault-ийн тэмдэглэлийн агуулга, хувийн өгөгдөл, 🔒 `03-Areas/Business/finances/private/`-ийн юуг ч issue-д хуулахгүй. Эргэлзвэл хасаад «vault-д байгаа» гэж бич.
- Token, нууц үг, API key асуухгүй, хэвлэхгүй, issue-д оруулахгүй.
- Хариултыг зохиохгүй: vault, CHANGELOG, номоос олдоогүй бол «мэдэхгүй байна, maintainer-ээс асууя» гэж шууд хэл.
- Issue давхардуулахгүй — `status`-аар өмнө нь ижил зүйл бичсэн эсэхийг шалга.
