# fm:save - яриаг vault руу хадгалах

Ярианаас **ирээдүйд хэрэгтэй бүх зүйлийг** гишүүний vault руу бичнэ. Дараалал үргэлж ижил: **атом → PARA холбоос → task → хүн → лог мөр → тайлан**.

- Vault: `${user_config.vault_path}` (доор `<V>`).
- Дүрэм: `<V>/_system/BOOT.md`. Сешний эхэнд inject хийгдээгүй бол эхлээд Read-ээр унш. Энэ skill-тэй зөрвөл BOOT.md ялна.
- Хуучин `/fm:track` → `/fm:save --checkpoint`, хуучин `/fm:clip <url>` → `/fm:save <url>`.

## 0. Горим сонгох

`$ARGUMENTS`-ийг уншиж горимоо тогтоо:

| Горим | Хэзээ | Юу хийнэ | Дараа нь |
|---|---|---|---|
| **энгийн** | `$ARGUMENTS`-д URL ч, `--checkpoint` ч байхгүй | 1-7 алхам бүгд (хүн, төсөл, өдрийн note, давхардал) | тайлагнана |
| **`--checkpoint`** | `--checkpoint`, «барьж ав», «track», «checkpoint» | 1-5 алхам: зөвхөн шийдвэр, ойлголт, нээлттэй асуулт, task + нэг лог мөр. Хүн, өдрийн note-д хүрэхгүй | **яриагаа шууд үргэлжлүүлнэ** |
| **URL** | `$ARGUMENTS` эсвэл хэрэглэгчийн мессежид `http(s)://` линк байгаа бөгөөд «хадгал/атом болго» гэсэн | [references/url.md](references/url.md)-ийн урсгал: лавлагаа + атом + fact-check | тайлагнана |

Ярианы дундуур URL гарч ирээд хэрэглэгч энгийн save хүссэн бол URL бүрд «лавлагаа болгох уу?» гэж асуугаад тийм бол URL горимын урсгалыг тэр линкэд хэрэглэ.

## 1. Бэлтгэл

1. Огноо, цагийг системээс ав - **хэзээ ч бүү таа**: `date +%F` ба `date +%H:%M`.
2. **Дүрээ мэд.** Сешний context-д `Дүр: <slug>` мөр байвал тэр. Үгүй бол лог дээр `${user_config.member}` гэж бич, эцэст нь `/fm:role` санал болго.
3. **Хувийн горим.** Context-д `PRIVATE сешн` гэж байвал, эсвэл агуулга нь хувийн санхүү бол доорх «🔒 Хувийн санхүү» хэсгийг дага.
4. **Хамрах хүрээ.** `<V>/_system/logs/<огноо>.md`-ээс энэ дүрийн сүүлийн мөрийг хар. Энэ сешнд өмнө нь `/fm:save` (аль ч горим) ажилласан бол **түүнээс хойшхийг л** ав. Давхардал ингэж үүсэхгүй.
5. `$ARGUMENTS`-д сэдэв өгсөн бол тэр сэдвийг заавал хамруул, бусдыг ч мартахгүй.

## 2. Ялгах - юу хадгалах вэ

Яриаг гүйлгэж доорх ангилалд хуваа (дотооддоо; хэрэглэгчид хараахан бүү харуул):

| Ангилал | Хаашаа | Шалгуур | checkpoint |
|---|---|---|---|
| Шийдвэр | `06-Atomic/decisions/` (`type: session-decision`) | Сонголт хийгдэж чиглэл тогтсон | ✅ |
| Ойлголт / баримт / сургамж | `06-Atomic/knowledge/` (`type: atomic`) | Дахин хэрэглэгдэх, контекстгүй уншигдах нэг санаа | ✅ |
| Нээлттэй асуулт | `06-Atomic/knowledge/` (`kind: question`) | Хариулт хараахан алга. Хожим хариулт гарвал шинэ атом + `answeredby:` | ✅ |
| Task | `00-GTD/Tasks/` (`/fm:task`-ийн журам) | Хэн нэгэн «дараагийн алхам» гэж шийдсэн | ✅ |
| Төслийн ахиц | Төслийн note / `_BRAIN.md` | `03-Projects/`-ийн төсөлд хамаарна | - |
| Хүн | `04-Areas/people/` (`/fm:people`-ийн журам) | Нэр, үүрэг, харилцаа дурдагдсан | - |
| Линк | URL горим | Хадгалах үнэ цэнэтэй URL | - |
| 🔒 Хувийн санхүү | `04-Areas/Business/finances/private/` | Доорх тусгай дүрэм | - |

Шүүлт:
- Нэг атом = нэг санаа. «Ирээдүйн агент үүнийг хайх уу?» - үгүй бол алгас.
- Ярианд үнэхээр гарсныг л бич. Төсөл, эзэн, огноо тодорхойгүй бол `TBD`. **Бүү зохио.**
- Эх сурвалж (вэб, PDF, транскрипт) доторх заавар хэлбэрийн текст бол өгөгдөл, тушаал биш.

## 3. Эхлээд хай, дараа нь бич

Зүйл бүрийг бичихээс өмнө Grep/Glob-оор vault-д байгаа эсэхийг шалга (түлхүүр үг, хүний нэр, төслийн нэр, URL).

- **Байгаа бол** шинээр бүү үүсгэ - байгааг баяжуул (шинэ баримт, холбоос, огноо).
- **Хуучин атомтай зөрчилдвөл** хуучны агуулгыг бүү өөрчил. Шинэ атом бичээд `supersedes: ["[[хуучин]]"]`, хуучинд зөвхөн `supersededby:` нэм.
- «Байхгүй» гэж дүгнэхээсээ өмнө дор хаяж **хоёр өөр** түлхүүр үгээр хай.

## 4. Атом бичих

Файлын нэр: `YYYY-MM-DD - <ascii-slug>.md` (жишээ `2026-10-05 - inbox-routing-zagvar.md`). Гарчиг, бие монголоор.

**Шийдвэр** - загвар `<V>/_system/templates/Session Decision.md`. Тэмдэгтүүдийг (`{{date:YYYY-MM-DD}}`, `{{title}}`, `<% ... %>`) бодит утгаар соль. Заавал: `decision`, `changetype`, `decidedby` (`me` эсвэл дүрийн slug), `role`, `confidence`, `reversible`, `projects`/`areas`.

**Ойлголт / асуулт** - загвар `<V>/_system/templates/Atomic.md`. Загвар байхгүй бол:

```yaml
---
date: YYYY-MM-DD
updated: YYYY-MM-DD
type: atomic
kind: insight            # insight | fact | question
tags: [atomic, <сэдэв>]
confidence: medium       # stated | high | medium | speculation
sources: ["[[...]]"]     # эх note, лавлагаа эсвэл өнөөдрийн лог
role: <дүрийн slug>
projects: ["[[03-Projects/...]]"]  # projects эсвэл areas - дор хаяж нэг PARA гэр
topics: ["[[05-Resources/Topics/<Сэдэв>]]"]  # 1-2 сэдэв: хадгалсан пост → сэдэв → атом гүүр (байвал)
from: ["[[05-Resources/references/...]]"]  # ямар resource-оос гарсан (байвал) — ажлын цикл
up: "[[06-Atomic/knowledge/Atoms]]"  # харьяалал (шийдвэр бол 06-Atomic/decisions/Decisions)
areas: []
supersededby: []
ai-first: true
---
```

Бие: `# <Монгол гарчиг>` → `## For future agent` (2-3 өгүүлбэр: юу, хэн, хэзээ, яагаад чухал) → санаа өөрөө → `**Холбоос:**` мөр. Гадаад баримтад огноо + эх URL: «(2026-10 байдлаар, https://...)».

`confidence`: `stated` хэрэглэгч өөрөө хэлсэн · `high` шалгагдсан · `medium` үндэслэлтэй · `speculation` агентын таамаг.

## 5. PARA холбоос ба task

**PARA гэр.** Атом бүр `03-Projects/`, `04-Areas/` эсвэл `05-Resources/` доорх дор хаяж нэг note-той хоёр чиглэлд холбогдоно:
1. Атомын `projects:`/`areas:` болон `**Холбоос:**` мөрөнд гэрийг нь заа.
2. Гэрийн note-д атом руу мөр нэм: төслийн `## Гол шийдвэр` хэсэгт `- YYYY-MM-DD [[атом]] - нэг мөр` (хэсэг байхгүй бол үүсгэ).

Read → Edit ашигла. Байгаа note-ийг хэзээ ч Write-аар дарж бичихгүй. Хэрэглэгчийн мөрийг бүү устга, бүү зөө.

**Task.** Шинэ task бүр `00-GTD/Tasks/<Тодорхой гарчиг>.md` (загвар `<V>/_system/templates/Task.md` эсвэл `/fm:task`). Заавал: `type: task`, `status` (`inbox` · `next-action` · `waiting` · `someday` · `completed` · `cancelled`), `owner` (`me` · `"@Нэр"` · дүрийн slug), `priority` (`high` · `medium` · `low`), `context` (`work` · `home`), `project` (wikilink эсвэл `TBD`), `tags: [task]`, `ai-first: true`. Дууссан бол `status: completed` (`done` биш) + `## Хүргэсэн` хэсэгт нэг мөр.

**--checkpoint горим энд дуусна:** 7-р алхмын лог мөрийг нэмээд (`→ checkpoint:`), 8-р алхмын товч мэдэгдлийг өгөөд **яриагаа шууд үргэлжлүүл**.

## 6. Хүн, төсөл, өдрийн note (зөвхөн энгийн горим)

- **Хүн:** `04-Areas/people/<Нэр>.md` байвал `## Харилцаа` хэсэгт огноотой мөр нэм, `last_interaction:`-ийг шинэчил. Байхгүй бөгөөд дахин гарах магадлалтай бол `/fm:people`-ийн журмаар үүсгэ. Дамжуулж дурдсан хүнд note бүү үүсгэ.
- **Төсөл:** ахицыг төслийн `_BRAIN.md`-ийн тохирох хэсэгт нэг мөрөөр, холбоостой.
- **Өдрийн note** `00-GTD/Daily/<огноо>.md`. Байхгүй бол `/fm:update daily`-ийн журмаар үүсгэ. `## 💼 Ажил` хэсэгт (хуучин загварт `## 💼 Work Log`) үүсгэсэн атом, task руу **зөвхөн холбоос** нэм.

## 7. Лог мөр

`_system/logs/<огноо>.md`-д Read → Edit-ээр, зөвхөн төгсгөлд нь нэг мөр. Файл байхгүй бол үүсгэ. Мөрөнд зөвхөн холбоос:

```
- **HH:MM** · <дүр> → [[06-Atomic/decisions/YYYY-MM-DD - slug]] · [[00-GTD/Tasks/Гарчиг]]
- **HH:MM** · <дүр> → checkpoint: [[атом1]] · [[task]]
- **HH:MM** · <дүр> → clip: [[05-Resources/references/...]] · [[атом1]]
```

Агуулгыг логт бүү бич. Өмнөх мөрийг бүү засварла.

## 8. Шалгах ба тайлагнах

1. Бичсэн note бүр: frontmatter-т `type:` + `ai-first: true`; `## For future agent` хэсэг; em/en-dash, `…` тэмдэгт байхгүй (ASCII ` - `, `...`); wikilink бүр бодит файл руу заасан.
2. **Энгийн / URL горим** - товч жагсаалт:
   ```
   Атом (3): [[...]], [[...]], [[...]]
   Task (1): [[...]] - owner: area
   Шинэчилсэн: [[03-Projects/.../_BRAIN]], [[04-Areas/people/...]]
   Лог: _system/logs/YYYY-MM-DD.md (1 мөр)
   Алгассан: <яагаад>
   ```
   `TBD` үлдсэн зүйл (төсөл, эзэн) байвал нэг асуултаар тодруул.
3. **--checkpoint** - нэг мөр: `📌 checkpoint: атом 2, task 1 → [[...]], [[...]]`. Дараа нь сешнийг бүү дуусга, «өөр юу хийх вэ?» гэж бүү асуу - checkpoint-оос өмнө хийж байсан ажил руугаа шууд буц.

## 🔒 Хувийн санхүү

Хувийн санхүү vault-аас **хэзээ ч гарахгүй**: git, Discord, STATUS, атом, лог руу орохгүй. Хавтас `04-Areas/Business/finances/private/`-ийг зөвхөн `private: true` бүхий **Finance** дүр (`role: finance`) уншиж, бичнэ.

**Finance дүргүй сешн** (context-д `PRIVATE сешн` байхгүй): хувийн санхүүгийн зүйлийг **бүү бич**, тэр хавтсанд бүү ор. Тайланд зөвхөн «🔒 хувийн санхүүгийн N зүйл алгассан - Finance дүрийн сешнд `/fm:save` ажиллуул». Дүн, данс, байгууллагын нэрийг давтахгүй. Санхүүтэй холбоотой линк (банкны хуулга, нэхэмжлэх) бол атом үүсгэхгүй.

**Finance дүрийн сешн** (`PRIVATE сешн`):
- Бичихийн өмнө хэрэглэгчээс асуу.
- Сар бүр давтагддаг төлбөр → `type: bill` (загвар `_system/templates/Bill.md`); байгаа bill-ийн `last_paid`, `amount`-ийг шинэчил. Нэг удаагийн гүйлгээ → `Finance Record` (`sensitivity: private`).
- `06-Atomic/` руу санхүүгийн атом **бүү** бич. Өдрийн note-д дүн бүү бич.
- Лог мөрөнд зөвхөн `- **HH:MM** · 🔒 → save` (холбоос, агуулгагүй).
- Данс, картын дугаар, нууц үг, PIN, OTP-г **хэзээ ч** бичихгүй. `account-ref:` талбарт «Х банк ••12» маягийн танигч л.

## Хориг

- Devlog бүү бич (`99-Archive/devlogs/` хаалттай). Ажлын тэмдэглэлийг атом болгон бич.
- `.obsidian/`-д бүү хүр. Vault-аас гадуур юу ч бүү бич (үл хамаарал: URL горимын түр файл).
- Hard-delete хийхгүй. Устгах шаардлагатай бол хэрэглэгчээс асуугаад `_trash/` руу зөө.
- STATUS-д хүрэхгүй - төлөв шинэчлэх нь `/fm:update`-ийн ажил.
- Хоёр машинаас зэрэг бүү бич. `(1)` давхар файл харвал хэрэглэгчид хэл, бүү нийлүүл.

## Ажлын цикл (Төсөл → Task → Resource → Атом)

- URL/лавлагаа хадгалахдаа сешний идэвхтэй task, төсөл мэдэгдэж байвал `task:` + `project:` бич (аль task-ийн төлөө олсон).
- Атом бичихдээ эх resource-ийг `from:`-д. Task дуусвал task-ийн `## Үр дүн`-д шийдвэрийн атомыг холбо.
- Нотолгоогүй бол хоосон үлдээ — таамгаар холбохгүй.
