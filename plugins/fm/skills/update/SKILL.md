# fm:update - ганц команд

**Хэрэглэгч зөвхөн `update` гэж бичнэ.** Бусад fm skill (`save`, `inbox`, `task`, `people`, `project`, `finance`) бол энэ командын **барилгын блок**: update тэдгээрийн журмыг (тухайн skill-ийн SKILL.md-г Read-ээр уншаад) дотроосоо гүйцэтгэнэ. Хэрэглэгчээс «одоо `/fm:save` ажиллуул» гэж хэзээ ч бүү гуй — өөрөө хий.

Vault: `${user_config.vault_path}` (доор `<V>`). Төхөөрөмж: `${user_config.device}`. Дүрэм: `<V>/_system/BOOT.md`.


> **Сешний нэр (itge.e 2026-10-15):** Шинэ сешн/agent нээх бүрт (Desktop fork, `start_session`/spawn, Workflow-ийн agent `label`, `/fm:role`/project сешн) нэрийг шууд тавина: «<ажлын icon> <ажил> › <дэд ажил>» — icon = ажлын төрөл (🎨 Creative · 🔍 Research · 📚 Wiki · 🏛️ Architect · 📁 төсөл · 📥 GTD); нээсэн сешн нь `mcp__ccd_session_mgmt__set_session_title`-аар (ToolSearch) тэр даруй нэрлэнэ.

## 0. Горим ба бэлтгэл

| `$ARGUMENTS` | Горим | Юу хийнэ |
|---|---|---|
| хоосон, текст, «шинэчил» | **оркестр** (анхдагч) | доорх 1-9 алхам |
| «хурдан» | оркестр-хурдан | 1, 2 (зөвхөн task), 8, 9 — inbox, хүн, төсөл алгасна |
| «daily», «өглөө», «өдрийн тэмдэглэл» | `daily` | (D) өдрийн note: фокус, хугацаа болсон task, өчигдрөөс |
| «дүгнэлт», «орой», «өдрөө хаая», «өдрийн дүгнэлт» | оркестр + (E) | 1-9 алхам + өдрийн дүгнэлт атом |
| «weekly», «долоо хоног», «тойм» | `weekly` | (W) долоо хоногийн тойм (+ оркестр-хурдан) |

1. Огноо, цаг, гарагийг системээс ав: `date +%F`, `date +%H:%M`, `date +%u` (1 = Даваа). **Хэзээ ч бүү таа.**
2. **Дүр.** Сешний context-ийн `Дүр: <slug>` мөр. Байхгүй бол: «Дүр тогтоогоогүй байна. `/fm:role <slug>` ажиллуулах уу, эсвэл `${user_config.member}` нэрээр шинэчлэх үү?» - хариу ирэхээс өмнө STATUS-д бүү бич.
3. **Хувийн горим.** Context-д `PRIVATE сешн` эсвэл дүрийн note-д `private: true` (Finance) бол доорх 🔒 хэсэг хүчинтэй.
4. **Хамрах хүрээ:** өнөөдрийн логоос энэ дүрийн сүүлийн `update`/`save` мөрийг ол — **түүнээс хойшхи** ярианы хэсгийг л боловсруул (давхардал үүсгэхгүй).
5. Албан ёсны `productivity` plugin-ий update-ийг **бүү** ажиллуул - тэр `TASKS.md`, `memory/` бичиж хоёр дахь санах ой үүсгэдэг. Энэ skill бүгдийг vault-д хийнэ.

6. **Хуучин бүтэц.** Vault-д `00-GTD`/`02-GTD`, `03-Projects`, `04-Areas`, `05-Resources`, `06-Atomic` зэрэг хуучин хавтас байвал (эсвэл `fm_brain_check` «дэд хавтсан дахь base» мэдээлбэл) гишүүнд санал болго: `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/fm_migrate.py" "<V>"` (dry run) → зөвшөөрвөл `--apply`. Дэлгэрэнгүй — `/fm:setup` 2.1.

|---|---|---|---|

## (A) Алхам 8 - STATUS мөр ба лог

1. Ярианаас (эсвэл `$ARGUMENTS`-аас) гарга: **Хийсэн** (1-3 зүйл) · **Зогссон** (юун дээр, хэнээс юу хүлээж байна) · **Дараагийн алхам**. 1-5-р алхамд үүссэн атом, task-ийн холбоосыг цуглуул.
2. **STATUS.md-д гараар бүү бич, хэрэв relay ажиллаж байвал** (`<V>/_system/fm/state/` хавтас байгаа = Discord relay тохируулсан). Тэр үед `relay.py hub` STATUS.md-г baton-уудаас (`_system/fm/state/<төсөл>.md`) бүхэлд нь дахин үүсгэдэг тул гараар хийсэн засвар дараагийн hub-д устна:
   - «Дараагийн алхам»: `python <relay.py> next "<хийсэн → зогссон → дараагийн алхам>" --sid <session id>` (baton-ийн `## ОДОО`-г Stop hook өөрөө бичнэ).
   - Самбарыг шууд шинэчлэх бол `python <relay.py> hub`.
   - Мөр нь **төсөл/baton тутам**, дүр тутам биш.
   **Relay байхгүй vault-д л** `<V>/_system/STATUS.md`-г гараар хөтөлнө — дүр бүр нэг мөр:
   ```markdown
   | Дүр | Сүүлд (огноо · төхөөрөмж) | Хаана зогссон → дараагийн алхам |
   |---|---|---|
   | [[GTD]] | YYYY-MM-DD HH:MM · <төхөөрөмж> | <хийсэн> → <зогссон> → <дараагийн алхам> · [[атом]] |
   ```
   - Read-ээр унш, өөрийн мөрийн 2, 3-р нүдийг л Edit-ээр соль; олдохгүй бол төгсгөлд нэм. Файл байхгүй бол үүсгэ (`type: system`, `updated:`, `ai-first: true`).
   - Нүд: нэг мөрөнд, `|` тэмдэгтгүй, ≤250 тэмдэгт, агуулга биш **холбоос**. Бусдын мөрөнд бүү хүр, Write-аар дарж бичихгүй.
3. Лог (`_system/logs/<огноо>.md`, Read → Edit, төгсгөлд): `- **HH:MM** · <дүр> → update · [[_system/STATUS]] · [[атом]] · [[task]]`
4. Discord relay тохируулсан бол (`/fm:relay`) Stop hook baton-ийг өөрөө бичнэ - энд юу ч бүү илгээ.

## (B) Алхам 9 - миний task-ууд, бусдын мэдээ

1. **Бусдын мэдээ.** `STATUS.md`-ийн бусад мөр, өнөөдрийн логийг унш. **Энэ дүрд хамаатай** зүйл (өөр дүр надаас юм хүлээж байна, давхардсан ажил, миний хүрээний шийдвэр) байвал ≤3 мөрөөр хэл. Үгүй бол юу ч бүү хэл.
2. **Нээлттэй task.** Эзэн тааруулах нь **төхөөрөмжөөс үл хамаарна** (`📚 Wiki` = PC, Mac аль алины Wiki сешн). `<V>/01-GTD/Tasks/`-д Grep-ээр (`-i` — том жижиг үсгийг үл хайхар, `output_mode: files_with_matches`) зөвхөн нэр дэвшигч ол. **Хайх үгс = энэ сешний бүх түлхүүрийн гол үгс:** сешний title (registry-ийн `sessions[sid].title`), дүрийн agent нэр (`roles[role].agent`), slug (`sessions[sid].role`) — тус бүрээс emoji, цэг таслал, `agent`/`pc`/`mac` үг ба төхөөрөмжийн нэрийг хасаад үлдсэн үг бүр (жишээ нь title `📚 Wiki · PC`, agent `📚 Wiki Agent`, slug `resource` → `wiki`, `resource`; title `✍️ Content Writer · Mac` → `content`, `writer`). Нэг ч үг алгасвал тэр нэрээр бичигдсэн task олдохгүй. Regex (`<үгс>` = `үг1|үг2|…`, regex-ийн тусгай тэмдэгтийг escape хий): `^(owner|responsible):.*(<үгс>)` ба owner/responsible-ийн YAML жагсаалтын мөрөнд `^\s*-\s.*(<үгс>)`. Төхөөрөмжийн дагавар бүү нэм. Дараа нь файл бүрийн frontmatter-ийг уншиж `owner` (скаляр эсвэл YAML жагсаалтын мөр бүр) ба `responsible`-ийг **тус тусад нь** хэвийн болго: emoji, цэг таслал (`·`, хаалт, `-`), `agent`/`pc`/`mac` үг ба төхөөрөмжийн нэрийг хасаад жижиг үсгээр (`📚 Wiki · PC`, `Wiki (PC)`, `Mac-Wiki`, `📚 Wiki Agent` → `wiki`). Энэ сешний түлхүүрүүдтэй (сешний title, дүрийн agent нэр, slug — мөн адил хэвийн болгосон) **яг тэнцүү** бол л таарна; хэсэгчилсэн таарлыг бүү тоол. Ерөнхий түлхүүр (`project`, `💼 Project Agent`) бол нэмэлтээр task-ийн `project:` (холбоосын сүүлийн хэсэг, жижиг үсгээр) нь сешний төслийн хүрээтэй тэнцүү байх ёстой — хүрээ = registry-ийн `sessions[sid].folder`-ийн сүүлийн хэсэг; байхгүй бол дүр нь `project` үед `sessions[sid].project`; тэр ч байхгүй бол `roles[role].project`. Хүрээгүй сешнд ерөнхий түлхүүр хэзээ ч таарахгүй. Дүргүй сешнд хэрэглэгчийн өөрийн task: `owner` **эсвэл** `responsible` нь `me`, `${user_config.member}`, түүний ASCII/хуучин хувилбар (жишээ нь `bd`, `BD`, `itge.e`) — **том жижиг үсгийг үл хайхар, `@` угтвар ба хашилтыг тайл** (regex: `^(owner|responsible):\s*["']?@?(me|<member>|<alias>)["']?\s*$`, `-i`). Хуучин утгуудыг ч тоол: `status: next` = `next-action`, `priority: high|medium|low` = 🔴🟡🟢. Олдсон task 0 бол «шалгуур vault-тай таарахгүй байж магадгүй» гэж хэлж, `owner:` утгуудын тоог (Grep count) харуул — хуурамч «0» тайлан бүү гарга. Frontmatter-аас `status`, `priority`, `due`, `project` (+ `in-progress` бол `claimed`, `started`)-ийг унш; `completed`, `cancelled` (хуучин `done`)-ийг хас — нээлттэй = `inbox · next-action · in-progress · waiting`. Эрэмбэ: ▶ `in-progress` (одоо хийгдэж буй, `claimed` · `started`) → хугацаа хэтэрсэн (⚠️) → priority (`high` → `medium` → `low`; хуучин 🔴 → 🟡 → 🟢) → `due`.
   | Task | Төлөв | Чухал | Хугацаа | Төсөл |
   |---|---|---|---|---|
3. Энэ сешнд дууссан task байвал зөвшөөрөл аваад `status: completed`, `completed: YYYY-MM-DD HH:MM` (системийн цаг; task өмнө нь `completed`/хуучин `done` биш байсан бол шинээр бич — хуучин утгыг дар; аль хэдийн `completed` бол бүү хөнд), `updated:`, «## Үр дүн»-д нэг мөр + шийдвэрийн атом (`fm_task.py done` цагийг өөрөө бичнэ).

## (D) daily - өдрийн тэмдэглэл

**Гол зарчим:** хэрэглэгчийн бичсэн юу ч **хэзээ ч дарж бичигдэхгүй**. Агент зөвхөн өөрийн хэсгүүдийг нэмж, шинэчилнэ. Огноо: `$ARGUMENTS`-д `YYYY-MM-DD` байвал тэр, үгүй бол өнөөдөр. Гараг: 1 Даваа · 2 Мягмар · 3 Лхагва · 4 Пүрэв · 5 Баасан · 6 Бямба · 7 Ням.

1. **Үүсгэх / нээх** `<V>/01-GTD/Daily/YYYY-MM-DD.md`.
   - Байхгүй бол `<V>/_system/templates/Daily Note.md`-г уншиж тэмдэгтүүдийг гараар соль (Obsidian ажиллаагүй тул plugin орлуулахгүй): `{{date:YYYY-MM-DD}}`, `{{date}}`, `<% tp.date.now("YYYY-MM-DD") %>` → огноо; `{{date:dddd}}` → монгол гараг; `{{title}}`, `<% tp.file.title %>` → `YYYY-MM-DD`; `{{time}}` → `HH:MM`; бусад `<% ... %>` → хоосон. Загвар байхгүй бол хамгийн бага бүтэц: frontmatter (`date`, `type: daily`, `tags: [daily]`, `ai-first: true`, `focus: []`), `# YYYY-MM-DD - <гараг>`, `## For future agent`, `## 🎯 Өнөөдрийн гол 3`, `## 💼 Ажил`, `## 🌙 Оройн дүгнэлт`.
   - Байгаа бол Read-ээр уншаад бүх өөрчлөлтийг **Edit-ээр, хэсэг хэсгээр**.
2. **Хөндөхгүй:** frontmatter-ийн `focus:`, `mood:`, `energy:`, `habit_*:`; `**Өдрийн зорилго:**`, `**Талархал:**`, `## 🏠 Хувийн`, `## 📥 Inbox`, оройн дүгнэлтийн хэрэглэгчийн мөрүүд, `> 💬 ...` сэтгэгдэл. Тэнд өнөөдрийн хүсэлт/асуулт бичсэн бол **шинэ оролт** гэж уншаад хариулах эсвэл task болгох эсэхийг асуу.
3. **Фокус** `## 🎯 Өнөөдрийн гол 3` (хуучин `## 🎯 Today's Focus`):
   - Хэрэглэгчийн `focus:` эхэнд (🔴 #1, 🟡 #2, 🟢 #3). Task хэзээ ч хэрэглэгчийн фокусыг шахахгүй.
   - `### 📌 Хугацаа болсон` - `01-GTD/Tasks/`-аас `due` ≤ өнөөдөр, нээлттэй, `owner`/`responsible` нь дээрх 2-р алхмын шалгуураар хэрэглэгч эсвэл энэ дүр: `- [[01-GTD/Tasks/<нэр>]] - due YYYY-MM-DD` (хэтэрсэн бол ⚠️).

   - Агентын дэд хэсгүүдийг (`📌`, `↪️`) дахин ажиллуулахад **бүхэлд нь сольж** шинэчил.
3б. **📅 Өнөөдрийн хуваарь** (issue #13, 2026-10-15) — Google Calendar connector-ийн `list_events` (ToolSearch «calendar list_events») сешнд байвал: өнөөдрийн event-үүдийг primary болон `📅 Уулзалт`, `🔁 Routine` calendar-аас (байвал) уншина; agent-ийн бичдэг `🤝 Task …`, `✅ Task …` calendar-ыг **алгас** (тэд task-аас үүсдэг, давхардана). `## 🎯 Өнөөдрийн гол 3`-ийн доор `### 📅 Өнөөдрийн хуваарь` хэсэгт цагийн дарааллаар `- HH:MM–HH:MM <гарчиг>` (бүтэн өдрийн event → `- бүтэн өдөр · <гарчиг>`); хувийн (`visibility: private`) event-ийн гарчгийг «🔒 хувийн» гэж бич. Agent-ийн хэсэг — дахин ажиллуулахад бүхэлд нь соль. Хэрэгсэл алга эсвэл алдаа бол чимээгүй алгас (зохиохгүй). Event үүсгэхгүй — зөвхөн уншина.
4. **Ажил** `## 💼 Ажил` (хуучин `## 💼 Work Log`): энэ яриа болон өнөөдрийн логийн атом, task, лавлагааны холбоос, мөр бүр `- [[...]] - нэг мөр`. Байгаа холбоосыг давтахгүй. Хуанлийн event-ийг энд бүү давт (3б-д).
   - **Task-ийн бодит цаг (decision 2026-10-09):** `01-GTD/Tasks/`-аас `started:` эсвэл `completed:` нь тэр өдрийн огноогоор эхэлсэн task-уудыг (Grep `^(started|completed):\s*["']?YYYY-MM-DD`) цагийн дарааллаар — `- HH:MM ✅ [[01-GTD/Tasks/<нэр>]] - <claimed>` (дууссан, `completed` цаг) · `- HH:MM ▶ [[01-GTD/Tasks/<нэр>]] - <claimed>` (одоо `in-progress`, `started` цаг). Дахин ажиллуулахад энэ дэд жагсаалтыг бүхэлд нь соль.
