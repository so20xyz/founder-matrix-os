# Context Engineer дүр — дизайн

Огноо: 2026-10-27 · Эзэн: Soyol · Бичсэн: Mac сешн (брэйнсторм) · Төлөв: батлуулахаар

## 1. Зорилго ба яагаад

Soyol-ын зорилго: AI command center-ийг **1%-ийн түвшинд** хүргэх, өөрөө system thinker, AI engineer болж өсөх (`00-Soul/Soyol.md`). Одоо fm-ийн дүрүүд (Architect, Creative, Project, Research, Wiki, GTD, Finance) ажлаа хийдэг ч **тэдний ажлын чанарыг хэн ч хэмждэггүй, хэн ч системтэй сайжруулдаггүй**. Prompt, BOOT, agent, skill-ийн өөрчлөлт «мэдрэмжээр» ордог.

Context Engineer нь шилдэг AI engineer-ийн ажлын мөчлөгийг fm-д авчирна: **бодит сешний бичлэгээс алдааг олж → тест (eval) болгож → context-ийг засаж → тоогоор нотолж → давтана.** Хоёр зүйлийг өсгөнө: **систем** (бүх дүрийн үр дүн) ба **Soyol** (AI engineer болох).

Soyol-ын хэлсэн тэргүүлэх зүйл: **token хэмнэх биш, үр дүн ба урт хугацааны өсөлт.** Token-ийг зөвхөн чанарт нөлөөлдөг учраас хэмжинэ (context дүүрэх тусам анхаарал сарниж, hallucination ихэсдэг).

### Үүнийг хөдөлгөсөн нотолгоо (2026-10-27-ны recon)

- Vault-ийн сешн бүр ажил эхлэхээс өмнө ~110–155k token context-тэй эхэлж байна (hook inject, `BOOT.md` 24 KB, skill/MCP жагсаалт).
- Урт сешнүүд 400k–967k token хүрдэг; Nomun Website сешн (`fd8019b7`, 117 мессеж, 885 tool call) 4 удаа хариулт дундаасаа тасарч, нэг удаа context дүүрч товчлогдсон, subagent-уудын ~60 тайлан үндсэн context руу буцсан.
- Ижил prompt 4 сешнд давтагдсан (Inai Newsletter).
- Сайн загвар ч бий: Nomun сешний эхний prompt зорилго, хугацаа, эх код, reference-тэй бүрэн байсан; бодит материал (зураг, намтар, бүтээлийн мэдээлэл) өгсөн; «тийм — X» батлалтаар жолоодсон; localhost дээр нүдээр шалгасан.

Эдгээр нь нэг сешний ажиглалт — **дизайныг үүн дээр бүү тулгуурла.** Алдааны ангилал бүх сешний trace review-оос гарна (§5.1).

## 2. Хамрах хүрээ

Шинэ дүр `context-engineer` (fm repo-д agent + vault-д дүрийн note), гурван давхаргатай:

| Давхарга | Хаана ажиллах | Юу хийх |
|---|---|---|
| **A. Нимгэн хаалга** | Сешн бүрийн дотор, зөвхөн эхний prompt дээр | Зорилго / гаралт / «болсон» шалгуурын аль нь дутуу байгааг шалгаж, дутуу бол **нэг** асуулт асуулгана. Өөр юу ч нэмэхгүй. |
| **B. Гол хөдөлгүүр** | Тусдаа Context Engineer сешн; долоо хоног бүр routine + Soyol дуудахад | Trace review → алдааны ангилал → eval → засварын санал (өмнөх/дараах оноотой). |
| **C. Soyol-ын өсөлт** | B-ийн гаралтын нэг хэсэг | Долоо хоногийн шошголох карт, «яагаад» тайлбар, prompt-ын оноо, алтан жишээ, glossary. |

### Горимууд (`/fm:role context-engineer` сешн дотор)

- `review` — сүүлийн тоймоос хойшхи бүх сешний trace-ийг уншиж алдааг ангилна.
- `eval` — eval-ийн багцыг ажиллуулж оноо гаргана (одоогийн context ба санал болгосон өөрчлөлтөөр).
- `audit` — статик context-ийн хэмжилт: сешн эхлэхэд юу inject хийгдэж, хэдэн token, аль хэсэг нь ашиглагддаг/үгүй.
- `brief` — Soyol-ын богино хүсэлтийг brief болгох (одоогийн `/ehle`-ийг сайжруулж, eval-тэй болгоно).

### Шилдэг AI engineer-ийн мөчлөг (Soyol баталсан)

1. **Trace review.** Бичлэгийг уншиж юу буруу болсныг бичнэ, бүлэглэж «алдааны ангилал» гаргана (жишээ: зохиосон баримт, буруу файл уншсан, context дүүрсэн, асуулгүй таамагласан). Хамгийн их давтагдсан 2–3 алдаа дараагийн засварын бай.
2. **Eval бичих.** Алдаа бүрт тийм/үгүй тест. Тестийг Soyol-ын шошготой тулгаж тааруулна: Soyol «муу» гэснийг тест ч «муу» гэх ёстой.
3. **Context төсөв.** Сешний эхлэлийн context хязгаартай; мэдээллийг хэрэгтэй үед ачаална; subagent зөвхөн товч тайлан буцаана; хүнд ажилд Opus, хөнгөнд Haiku/Sonnet.
4. **Prompt-ыг код шиг.** Agent, skill, BOOT-ийн өөрчлөлт бүр eval-ийн өмнөх/дараах оноотой. Оноо унавал буцаана.
5. **Prompt засагч.** Богино хүсэлт → brief.
6. **Өөрийгөө сайжруулах.** Context Engineer-ийн өөрийн санал ч eval-ээр шалгагдана; өөрийнхөө ажлыг «сайн» гэж дүгнэх эрхгүй.

## 3. Зорилго биш / хориг (anti-goals)

- **Ажлын сешн бүрт хүнд agent байлгахгүй.** A давхарга л дотор нь; бусад нь гадна. Шалтгаан: нэмэлт context ажлын сешний чанарыг өөрөө бууруулна.
- **Өөрийгөө дүгнэхгүй.** Засвар санал болгосон агент тэр засварын eval-ийг шүүхгүй (шүүгч нь тусдаа, Soyol-ын шошгоор тааруулсан).
- **Нотолгоогүй засвар оруулахгүй.** Eval-ийн өмнөх/дараах оноогүй өөрчлөлт repo-д орохгүй; Soyol батлахгүй бол орохгүй.
- **AI slop биш.** Оноо өсөхгүй байхад урт тайлан үйлдвэрлэх нь бүтэлгүйтэл. Долоо хоногийн гаралт товч, шийдвэр рүү чиглэсэн.
- **Soyol-ын ажлыг хүндрүүлэхгүй.** Шошголох ажил долоо хоногт ~15 мин орчим; A хаалга зөвхөн дутуу үед, нэг асуулт.
- 🔒 Finance дүрийн сешн, `03-Areas/Business/finances/private/`-ийн агуулгыг уншихгүй, eval-д оруулахгүй, тайланд иш татахгүй.
- Бусад гишүүний (BD/itge.e) сешнийг тэдний зөвшөөрөлгүй review хийхгүй.
- Бодит сешний агуулга (prompt, харилцагчийн нэр, файлын агуулга) **fm repo-д орохгүй**; repo-д зөвхөн код, загвар, нийтлэг дүрэм.
- **Гишүүний карт, шошго, ишлэл, eval-ийн кейс, тайлан бусад гишүүнд харагдахгүй** (Soyol 2026-10-27: «BD-д харагдахгүй»). Хуваалцсан vault-д зөвхөн нэр хаягүй алдааны ангилал орно (§5.3).

## 4. Хязгаарлалт

- Код ганц repo `founder-matrix-os` (`plugins/fm/`): agent `agents/context-engineer.md` (бусад agent-ийн «нимгэн заагч» хэв маягаар), скрипт `scripts/`, тест `scripts/test_*.py` (Python 3.9+, standard library, Windows-safe — `fm_context.py`-ийн адил).
- Дүрийн бүрэн тодорхойлолт vault-д: `03-Areas/AI Team/ai-workers/Context Engineer.md`, `_system/fm/registry.json`-д `roles.context-engineer` бүртгэл (одоогийн дүрүүдийн бүтэцтэй адил: `note`, `channel`, `group`, `skills`, `agent`).
- Гишүүн бүрт ажиллах ёстой (fm бол олон гишүүний plugin): Soyol-д хатуу кодлогдсон зүйл кодонд орохгүй; гишүүний нэр, зорилго vault/config-оос.
- Өгөгдлийн эх: Claude Code транскрипт `~/.claude/projects/*/*.jsonl` (машин бүрт локал). PC ↔ Mac: одоогийн harvester (`per-device` routine, `tools/relay/harvest.py`)-ийн замыг дагаж машин бүр өөрийн trace-ийн **хураангуй**-г vault руу бичнэ; бүтэн транскрипт Drive руу хуулагдахгүй.
- Долоо хоногийн ажиллагаа Claude Desktop-ийн Scheduled routine (`plugins/fm/routines/` загвар, `/fm:setup`-ээр гишүүний зөвшөөрлөөр үүсгэнэ).
- A хаалга hook-оор хэрэгжвэл: `hooks.json`-д нэмэгдэх inject нь жижиг (зорилтот ≤ 1 KB), зөвхөн сешний эхний хэрэглэгчийн prompt дээр, vault-аас гадуур чимээгүй, алдаа гарвал exit 0 (одоогийн hook-уудын дүрэм).
- Commit/push зөвхөн Soyol хэлсэн үед; `main` дээр биш (`feat/context-engineer`).

## 5. Soyol-ын шийдсэн «хэрхэн»

1. **Гаднаас тогтмол шалгах нь гол** (сешн бүрийн дотор байнга биш). Дотор нь зөвхөн нимгэн хаалга (§2 A). Soyol: «аль нь илүү үр дүнтэй вэ, тэрийг хий — token чухал биш, үр дүн ба урт хугацааны хөгжил чухал».
2. **Дизайн нэг сешний дүгнэлтэд тулгуурлахгүй** — бүх сешний trace review-оос алдааны ангилал гарна.
3. **Prompt засагч, Context аудитор, Eval хийгч** гурван функц + шилдэг AI engineer-ийн мөчлөг (§2) — Soyol хоёуланг нь «таалагдсан» гэж баталсан.
4. **Soyol өөрөө шошголно**, хугацаа хязгааргүй («хэдэн минут ч байж болно — урт хугацаандаа би өөрөө хөгжих, илүү үр дүнтэй ажиллахтай холбоотой»). Тиймээс шошго нь eval-ийн «алтан үнэн», C давхарга заавал.
5. Мөчлөг долоо хоног бүр + Soyol дуудахад.

### 5.1 Мөчлөгийн нарийвчлал

**Trace review (`review`):**
- Сешн бүрийг нэг **карт** болгоно: дүр, эхний prompt (товч), мессеж/tool тоо, эхлэлийн ба оргил context, тасралт/товчлол/«Try again» тоо, subagent тайлангийн хэмжээ, Soyol-ын засвар хэлсэн мөрүүд, батлалтууд, эцсийн үр дүн (commit, файл, task хаагдсан эсэх).
- Механик хэмжүүрийг скрипт тооцно (LLM биш). Алдааг тэмдэглэх (open coding) ба бүлэглэхийг LLM хийнэ; бүлэг бүр бодит мөрийн ишлэлтэй.
- Гаралт: алдааны ангилал (давтамжаар эрэмбэлсэн), долоо хоногийн шошголох картууд.

**Шошго (C):** Soyol карт бүрт «сайн/муу» + нэг мөр шалтгаан. Эхний хэдэн долоо хоногт шошго дээр тулгуурлаж шүүгчийг тааруулна.

**Eval (`eval`)** — хоёр төрөл:
- **Trace eval:** бодит сешнийг алдааны ангилал бүрийн тийм/үгүй шалгуураар дүгнэх шүүгч. Шүүгч Soyol-ын шошготой хэр таарч байгааг (agreement) тайланд үргэлж харуулна; таарц бага бол шүүгчийн оноонд итгэхгүй гэж тэмдэглэнэ.
- **Regression eval:** тогтмол даалгаврын багц (бодит сешнээс авсан, нууц мэдээллийг арилгасан) — context-ийн хуучин ба шинэ хувилбараар ажиллуулж pass-rate, эхлэлийн token, хариулах хугацааг харьцуулна. Claude-ийн шинэ загвар гарахад ч ижил багцаар.
- Механик хэмжүүр (эхлэлийн context, оргил, тасралт) — шүүгчгүй, шууд тоо.

**Засварын санал:** нэг санал = нэг өөрчлөлт (BOOT, agent, skill, hook, дүрийн note), ямар алдааны ангиллыг засах, өмнөх/дараах оноо, буцаах арга. Soyol батлавал Architect-ийн урсгалаар (SDD, тест) repo-д.

**Soyol-ын өсөлт (C):**
- Алдаа бүрийн ард ямар context engineering зарчим байгааг энгийн монголоор тайлбарлана; шинэ ойлголт → Wiki-ийн glossary/атом (Wiki дүрт task).
- **Prompt-ын оноо:** Soyol-ын сешний эхний prompt-ууд зорилго / материал / «болсон» шалгууртай байсан эсэх — долоо хоногоор чиг хандлага.
- **Алтан жишээ:** хамгийн сайн шошготой сешнүүдийн загвар (жишээ нь Nomun Website-ийн эхний prompt) хадгалагдаж, `brief` горим тэднээс суралцана.

### 5.2 Амжилтын шалгуур («болсон» гэж юуг хэлэх)

- v1 болсон: дүр бүртгэгдсэн; `review` нэг долоо хоногийн бүх (Finance-аас бусад) сешнийг карт болгож, алдааны ангилал гаргадаг; Soyol шошголж чаддаг; `eval` механик хэмжүүр + дор хаяж нэг trace eval + regression багцын эхний 10–15 кейстэй ажилладаг; A хаалга ажилладаг; долоо хоногийн routine үүсгэх загвартай; скриптүүд тесттэй.
- Урт хугацааны амжилт (хэмжих, амлах биш): Soyol-ын «сайн» шошготой сешний хувь өсөх; хамгийн давтагддаг алдааны ангиллын давтамж буурах; шүүгч ↔ Soyol таарц өсөх; Soyol-ын prompt-ын оноо өсөх.

### 5.3 Claude-ийн шийдсэн зүйл (builder шалгалтын дараа; Soyol шалгана)

1. **Аль trace-ийг уншиж:** зөвхөн vault хавтас ба түүний дэд хавтаснуудад (жишээ `02-Projects/*`) нээгдсэн сешн — `~/.claude/projects/-Users-<user>-…Founder-Matrix*`. Бусад repo, `~/Documents/Brain` (Tuvshin) зэрэг орохгүй. v1-д fm repo-гийн сешн орохгүй.
2. **Fail closed:** сешний дүр `finance` бол, эсвэл транскрипт `finances/private` замд хүрсэн бол, эсвэл дүр/гишүүн тодорхойгүй ба санхүүгийн шинжтэй бол → алгасна (LLM ангилалд найдахгүй). Алгассан тоог л тайланд бичнэ.
3. **Гишүүн тус бүрээр:** Context Engineer гишүүн бүрт тусдаа ажиллана — зөвхөн тухайн машины эзний сешн, эзний шошго, эзний шүүгчийн тааруулга. Багийн нийтлэг зүйл зөвхөн нэр хаягүй алдааны ангилал ба repo-д орох засвар.
4. **LLM review хаана:** машин бүрт локал (routine нь `per-device`). Транскрипт машинаас гарахгүй.
5. **Хувийн өгөгдлийн байршил (Soyol-ын шийдвэрийг хэрэгжүүлэх арга):** карт, шошго, ишлэл, eval-ийн кейс, тайлан нь **хуваалцсан Google Drive vault-аас гадуур**, машины локал хавтсанд (`~/.fmos/context-engineer/`) хадгалагдана. Шалтгаан: vault-ийн доторх «private» хавтас ч Drive-аар BD руу синк болдог тул зөвхөн дүрмээр хамгаалагдана; vault-аас гадуур бол бодитоор харагдахгүй. Ишлэл ≤ 200 тэмдэгт, харилцагч/хүний нэр, файлын агуулга, URL-ын query, token/key-г арилгасан. Vault руу (`03-Areas/AI Team/` дор) зөвхөн **нэр хаягүй алдааны ангилал** (ангиллын нэр, тодорхойлолт, давтамж; ишлэлгүй, сешний нэргүй). Хязгаар: PC ба Mac тус бүр өөрийн карт/шошготой; хоёр машины өгөгдлийг нэгтгэх нь v1-д орохгүй (дараа нь хувийн git repo эсвэл шифрлэсэн синкээр).
6. **Regression eval-ийн тусгаарлалт:** vault-ийн түр хуулбар дээр, Discord/relay, Notion, Gmail, Slack зэрэг гадагш бичдэг MCP болон git push унтраастай ажиллана. Pass/fail нь кейс бүрийн тогтмол шалгалтаар (файл үүссэн эсэх, асуулт асуусан эсэх, token ≤ хязгаар г.м.), шаардлагатай хэсэгт шүүгчээр. Төсвийн хязгаар тавихгүй (Soyol: token чухал биш), гэхдээ ажиллуулалт бүрийн token-ийг тайланд харуулна.
7. **A хаалга ба одоогийн дүрэм:** A хаалга fm-д бүх гишүүнд. Slash command-аар эхэлсэн prompt, resume/compact, routine/relay-ээс эхэлсэн headless сешнд ажиллахгүй. Soyol-ын глобал `CLAUDE.md`-ийн «Clarify once» ба `/ehle` хэвээр үлдэнэ; eval A хаалга тэднийг бүрэн орлож байгааг харуулсны дараа л хасах саналыг Soyol-д тавина.
8. **Шүүгчийн итгэлцэл:** v1 нь шүүгч + тааруулах урсгалтай гарна, гэхдээ шүүгч Soyol-той ≥ 80% таарч, ≥ 30 шошготой карт хуримтлагдах хүртэл засварын санал зөвхөн механик хэмжүүр ба Soyol-ын шошгоор нотлогдоно.

## 6. Builder-т үлдээсэн зүйл

- Скрипт, файлын нэрс, eval-ийн өгөгдлийн формат (JSONL, YAML…), `~/.fmos/context-engineer/` доторх бүтэц, vault дахь нэр хаягүй ангиллын note-ийн яг нэр.
